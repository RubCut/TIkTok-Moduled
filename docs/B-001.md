# B-001: исходный обработчик сбоев — статус дефекта

**Статус: НЕ ЗАКРЫТ.** Требование ТЗ §18.2/§18.6 и приёмки §25: дефект
закрывается только по реальному stack trace с устройства. Исходников TikTok и
реального stack trace B-001 предоставлено не было, поэтому исправление
«вслепую» было бы имитацией.

## Что поставлено вместо имитации (диагностический контур)

1. **Сохранение до передачи** (`core/CrashReports.installWithPrevious`):
   обработчик TModules сохраняется в файл ПОСЛЕ фиксации предыдущего
   (исходного) обработчика хоста и вызывает его после записи отчёта. Порядок
   гарантирует, что отчёт сохраняется локально до передачи управления
   исходному обработчику (§18.2).
2. **Проверка записи и замены handler** (§18.2):
   - `CrashReports.verifyHandlerStillInstalled(expected)` — обнаруживает
     замену обработчика хостом или другой библиотекой;
   - `FailureListener.onReportFailure/onReportTruncated` — сбои записи
     (нет места, права, обрыв) фиксируются явно, а не теряются молча;
   - runtime вызывает проверку при старте и пишет различимое состояние в
     журнал (`CRASH_HANDLER_REPLACED` / `CRASH_STORAGE_FAILURE`).
3. **Дедупликация и лимиты**: отчёты ограничены 5 × 1 MiB (`Limits`),
   состояние crash-политики — строковый файл с форматом `key value`
   (ошибка формата = «состояние повреждено», а не молчаливый сброс).
4. **Экран диагностики менеджера**: раздел B-001 показывает состояние
   обработчика, покрытие (только Java-сбои после установки обработчика;
   native-сбои и ANR не покрыты — §18.3) и кнопки «Скопировать»/экспорт.
   Автокопирование в буфер — только по явному согласию (§18.5).
5. **Отдельный контур TModules** (§18.4): сбои самого менеджера пишутся в его
   собственное хранилище (`TModulesApplication`), не смешиваясь с отчётами
   хоста.

## Что нужно для закрытия

1. Реальный stack trace B-001 с устройства (logcat/tombstone/отчёт
   обработчика хоста).
2. Анализ: кто устанавливает исходный обработчик (хост, crash-SDK, система) и
   в какой момент он заменяется.
3. Исправление в `CrashReports`/`CrashReporter` + регрессионный тест,
   воспроизводящий последовательность установок/замен.
4. Подтверждение на эталонном устройстве (ADR-0006).

Без пунктов 1–2 любой «фикс» был бы unverifiable guesswork, поэтому поставка
фиксирует честное состояние: контур есть, дефект открыт.
