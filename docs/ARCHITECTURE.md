# Архитектура TModules

## Компоненты и границы

```
+-------------------+        +--------------------+
|  TModules (APK)   |        | Патченный TikTok   |
|  менеджер         |  мост  | (тот же сертификат)|
|  - патчер         |<------>|  runtime (DEX)     |
|  - хранилище      | (IPC)  |  - загрузка модулей|
|  - каталог        |        |  - safe mode       |
|  - 9 экранов MD3  |        |  - crash-контур    |
+-------------------+        +--------------------+
        ^                             |
        | установка ZIP               | onLoad(ModuleContext)
+-------------------+                 v
| Каталог (Pages)   |        +--------------------+
| descriptor + ZIP  |        | Модули (DEX)       |
+-------------------+        | sample/region/...  |
                             +--------------------+
```

- **core** — чистый Java: лимиты, валидаторы (манифест, архив, DEX, конфиг),
  снимок и его кодек, контракт моста, descriptor, индекс каталога, политика URL,
  атомарная запись файлов, crash-политика и отчёты. Без Android-зависимостей.
- **module-api** — контракт автора: `TModule`, `ModuleContext` (`API_VERSION=1`,
  фиксирован), `ConfigSnapshot`, `ModuleLogger`, `HookApi`, `HostInfo`,
  `RestartResult`. Без MD3 (§21.1).
- **runtime** — Android-библиотека, встраиваемая в хост как DEX:
  `RuntimeApplication` (точка входа в manifest), `RuntimeBootstrap`
  (идемпотентная инициализация), загрузчик DEX с отдельными ClassLoader,
  снимки (мост → кеш), safe mode, crash-репортёр, `SafeModeRecoveryActivity`.
  Не зависит от standalone-ui/MD3 (§21.1).
- **patcher** — чистый Java + apksig: анализ APK (AXML-парсер), профиль
  совместимости, план, детерминированное разрешение конфликтов, правка manifest
  (только точка входа + recovery-экран), пересборка, подпись v1+v2+v3,
  независимая проверка результата.
- **manager** — Android-приложение TModules: хранилище модулей (атомарная
  установка staging→verify→publish с откатом), снимки, настройки, репозитории
  с кешем, мост (`BridgeProvider` + `BridgeGuard`), 9 MD3-экранов.
- **модули** — отдельные ZIP (`module.json` + `classes.dex`), собираются D8.

## Поток установки модуля

1. Вход: локальный файл, загрузка из репозитория или комплектный модуль.
2. Проверки: манифест (`apiVersion=1`, ID, targetPackages), DEX-заголовок,
   состав архива (ровно 2 записи), SHA-256 архива (для репозитория — сверка с
   descriptor и значимыми полями манифеста).
3. Публикация: staging-каталог → проверка → атомарный move; откат при сбое.
   Новый сторонний модуль — выключен; замена ID и смена ключа — отдельные
   подтверждения.
4. `SnapshotStore.buildNext` собирает снимок (поколение, список, версии, хеши)
   и публикует его атомарно: candidate → active, прежний active → previous.
5. Изменения применяются только после перезапуска хоста: runtime читает снимок
   при старте (мост → локальный кеш).

## Поток патча

1. Анализ входа (без изменения файла): manifest, DEX, ABI, подпись, маркеры.
2. План: профиль, точка входа, ABI-исключения, конфликты, повторный патч,
   подпись. Блокеры останавливают патч до изменений.
3. Пересборка во временном каталоге → подпись сохранённым ключом → проверка
   (подпись, manifest, package ID, launcher, authorities, записи) → атомарная
   публикация в `/storage/emulated/0/tmoduled`.

## Мост (IPC)

`content://dev.moduled.manager.bridge`, permission
`dev.moduled.manager.permission.BRIDGE` (signature). `BridgeGuard` проверяет
UID и сертификат вызывающего, `moduleId` — по списку установленного. Пути к
файлам не принимаются из IPC-параметров: только внутренние реестровые пути
(DEX/конфиг), выдаются read-only через `openFile`. Методы: `getSnapshot`,
`getModuleState`, `getDiagnostics`, `reportEvent`; `requestRestart` и
`resetSafeMode` отклоняются явными кодами (перезапуск — задача runtime хоста).

## Безопасность и приватность

- Исполняемые файлы, ключи и снимки — только внутреннее хранилище (§20.4);
  `/storage/emulated/0/tmoduled` — исключительно готовые артефакты.
- Секретный ключ подписи не появляется в исходниках, логах, отчётах и
  артефактах; наружу — только отпечаток сертификата.
- Сеть: только каталог/descriptor/архивы, только HTTPS, редиректы
  перепроверяются, лимиты размеров, отмена; при старте runtime сети нет (RUN-03).
- Журналы: уровни приватности MINIMAL/NORMAL/VERBOSE; автокопирование
  crash-отчёта в буфер — только по явному согласию (§18.5).
