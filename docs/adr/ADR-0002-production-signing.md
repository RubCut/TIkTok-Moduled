# ADR-0002: production-подпись отделена от разработческой (§7.4, §15.4)

**Статус:** принято.

**Решение.**
1. В поставке автоматически создаётся только разработческий самоподписанный
   ключ (RSA 4096, SHA256withRSA, PKCS12) во внутреннем хранилище менеджера
   (`files/tmoduled/keys`). Он сохраняется между патчами: обновления
   устанавливаются без удаления приложения.
2. Production-ключ НИКОГДА не создаётся автоматически, не хранится в
   репозитории и не выводится в логи/отчёты/артефакты. `SigningKeys.loadOrCreate`
   с `Kind.PRODUCTION` возвращает явную ошибку `SIGNING_PRODUCTION_FORBIDDEN`.
3. Схемы подписи: v1+v2+v3 (apksig). Ротация ключа (v3 rotation) — открытое
   решение до появления production-ключа.
4. Конфликт подписи показывается ДО установки (в плане патча), а не после.

**Обоснование.** Секретный ключ в репозитории или артефактах — критическая
утечка; debug-подпись не должна выдаваться за production (§15.4).

**Последствия.** Production-сборка патченного APK возможна только после
подключения внешнего хранилища ключа отдельным изменением с review.
