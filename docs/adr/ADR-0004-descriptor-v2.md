# ADR-0004: descriptor v2 — отказ до появления потребности (§10.2, §28)

**Статус:** принято (v1 зафиксирована).

**Решение.** Descriptor v1 = внутренний манифест (`id`, `name`, `description`,
`version`, `versionCode`, `apiVersion=1`, `entrypoint`, `targetPackages`) +
транспортные поля (`downloadUrl` HTTPS, `archiveSha256` — SHA-256 точных
байтов ZIP, `iconUrl`, `screenshots`, `authorName`, `authorUrl`, `sourceUrl`,
`authorKeyFingerprint`, опциональная `signature`). Неизвестные поля
отклоняются (`DESCRIPTOR_UNKNOWN_FIELD`): новые поля требуют новой версии
схемы.

V2 не вводится: неизвестные поля v1 не принимаются, поэтому эволюция схемы
возможна только явной версией. Поле `signature` зарезервировано под подпись
descriptor авторским ключом; алгоритм и ротация — открытое решение (§28) до
первого реального использования.

**Обоснование.** «Сравнение по значимым полям» (§10.2) требует строгой схемы:
молчаливое принятие неизвестных полей сделало бы подмену descriptor
неотличимой от обновления.
