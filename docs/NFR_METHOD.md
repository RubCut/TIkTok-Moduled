# Методика проверки НФТ (§23) — до приёмки

## 1. Накладные расходы runtime без модулей

**Требование:** p95 ≤ 200 мс и ≤ +20 MiB PSS относительно непатченого хоста,
не менее 30 запусков.

**Методика:**

1. Эталонное устройство (ADR-0006), одна и та же сборка хоста: A — непатченый
   APK, B — патченый APK без включённых модулей (снимок пуст).
2. Для каждого варианта: 35 холодных стартов подряд
   (`adb shell am force-stop <pkg>` → `am start -W <pkg>/<launcher>`),
   между стартами 10 с паузы. Первый прогон каждого дня — прогревочный, в
   статистику не входит.
3. **Время:** `am start -W` TotalTime + внутренняя метка runtime:
   `BOOTSTRAP_START` → `BOOTSTRAP_DONE` в `runtime.log` (runtime пишет
   длительность ранней синхронной фазы сам, RUN-04). Накладные расходы =
   p95(B.TotalTime − A.TotalTime) по совмещённым запускам и отдельно
   p95(BOOTSTRAP_DONE − BOOTSTRAP_START).
4. **Память:** через 20 с после каждого старта —
   `adb shell dumpsys meminfo <pkg>` → TOTAL PSS. Прирост =
   p95(PSS_B) − p95(PSS_A).
5. Условия: температура устройства в норме (без троттлинга: пауза при
   `Thermal throttling` в logcat), Wi-Fi выключен (RUN-03 проверяется
   отдельно: `tcpdump`/logcat не должны показать сетевых запросов runtime при
   старте), фоновые приложения закрыты.
6. Критерий приёмки: оба p95 в лимите; иначе — оптимизация ранней фазы
   (перенос чтения снимка/журнала с основного потока) и повторный замер.

**Результат первой поставки:** НЕ ЗАМЕРЯНО — эталонное устройство с реальным
хостом не предоставлено (ADR-0006). Замер на demo-host фиксируется отдельно и
не переносится на TikTok без оговорок.

## 2. Надёжность хранения (§23.2)

- Все записи состояния атомарны: temp → fsync → rename (`AtomicFile`);
  checked-тесты покрывают прерывание между этапами.
- Нехватка места: `AtomicFile` сообщает `ENOSPC` кодом ошибки, старый файл
  сохраняется (тест `AtomicFileTest`).
- Валидация входов: манифест/архив/DEX/конфиг/descriptor/каталог — явные коды
  ошибок, неизвестные поля отклоняются.
- Обязательной сети нет: установка из файла, снимок и safe mode работают
  офлайн; сеть — только явные действия пользователя в каталоге.

## 3. Журнал и приватность (§23.3)

Уровни: MINIMAL (только коды событий), NORMAL (+ идентификаторы модулей),
VERBOSE (+ сообщения модулей). Секреты (пароль ключа, приватный ключ) не
пишутся ни на одном уровне; тексты ошибок санитизируются
(`SigningKeys.safeMessage`).
