# Каталог и модерация (ТЗ §13, §28)

## Адрес каталога

Каталог публикуется на GitHub Pages репозитория:

- индекс: `https://rubcut.github.io/TIkTok-Moduled/catalog.json`;
- descriptor'ы модулей: `https://rubcut.github.io/TIkTok-Moduled/descriptors/<id>.json`;
- архивы модулей: прикреплённые файлы релизов GitHub (`https://github.com/RubCut/TIkTok-Moduled/releases/download/...`).

Схема индекса (§13.1):

```json
{
  "schemaVersion": 1,
  "name": "TModules Catalog",
  "modules": [
    { "id": "...", "name": "...", "description": "...", "manifestUrl": "https://..." }
  ]
}
```

Правила, которые проверяются в CI (workflow `Pages`):

- `schemaVersion` равен 1;
- ID модулей уникальны (дубли в источнике запрещены);
- все URL — HTTPS (HTTP downgrade запрещён, §13.2);
- обязательные поля присутствуют.

## Модель доверия и модерация

Каталог **не проверяет код модулей автоматически**. Модуль выполняется с правами
процесса хоста (§14.1), поэтому:

1. В основной каталог попадают только модули, собранные в этом репозитории CI
   (комплектные: `dev.moduled.sample`, `dev.moduled.region`,
   `dev.moduled.inapp.manager`). Их descriptor'ы генерируются из артефактов
   сборки, поэтому `archiveSha256` всегда соответствует точным байтам ZIP.
2. Сторонние модули добавляются в каталог только решением сопровождения
   репозитория (review + явное указание автора и источника). Пользователь в
   приложении в любом случае видит автора, источник, отпечаток ключа и
   подтверждает доверие перед включением (§11.8, §14.2).
3. Установка из «непроверенных» источников поддерживается штатно: пользователь
   может добавить свой источник каталога или установить ZIP из файла. Ответственность
   за такой код несут автор и пользователь, включивший модуль.

## Публикация descriptor'ов

Descriptor'ы генерируются скриптом `.github/scripts/publish-descriptors.py` из
артефактов сборки: он берёт готовый ZIP модуля, считает SHA-256 точных байтов
архива (не содержимое внутри ZIP) и записывает descriptor со ссылками на файлы
релиза. Скрипт вызывается в workflow релиза; публикация релиза — отдельное
действие пользователя (§26.6).
